# 设计说明

> 本文记录系统架构、关键设计决策及其取舍依据。面向希望理解「为什么这样实现」的开发者。
> 部署与操作说明见 [DEPLOYMENT.md](DEPLOYMENT.md)，发布验证见 [VERIFICATION.md](VERIFICATION.md)。

---

## 1. 概述

### 1.1 设计目标

| 目标 | 指标 | 来源约束 |
|---|---|---|
| 近距成像 | 0.2 mm 特征 @ 100 mm 工作距离下 ≥ 3 px | 特征可辨识性 |
| 单张体积 | ≤ 500 KB | TF 卡容量与后续传输带宽 |
| 响应速度 | 会话内按键 → 落卡 ≤ 3 s；深睡唤醒 → 落卡 ≤ 5 s | 现场手持操作节奏 |
| 续航 | 深睡 ≤ 20 µA，24~48 张/天条件下 ≥ 60 天 | 18650 单节容量 |
| 无人值守 | 无操作自动休眠，掉电不丢参数 | 现场无维护条件 |

### 1.2 核心约束

- **无操作系统层**：裸 ESP-IDF，单主流程 + 少量 FreeRTOS 任务（命令行 REPL、TWDT）。
- **无交互界面**：只有一颗按键 + 声音 + LED，所有配置通过串口或 NVS。
- **不联网**：Phase 1 完全离线，数据以 JPEG 形式落在 TF 卡。
- **不本地处理图像**：固件只负责「拍到、存好」，不做识别或压缩以外的处理。

### 1.3 状态机

```
        上电 / 深睡唤醒
              │
              ▼
      ┌───────────────┐   短按 PWR    ┌──────────┐
      │  唤醒会话      │ ────────────▶ │ 拍照流程  │
      │ hold_awake_s  │ ◀──────────── │ 存卡+反馈 │
      └───────────────┘   重置计时      └──────────┘
              │
    ┌─────────┼─────────┐
    │         │         │
 长按>1.5s  超时      sleep 命令
    │         │         │
    └─────────┴─────────┘
              ▼
          深睡（ext1 唤醒）
```

**关键语义**：深睡中的第一次按键只用于**唤醒**，不触发拍照。这样「掏出来按一下」不会产生废片；需要拍照时再按一次。

## 2. 硬件约束

| 项 | 事实 | 设计影响 |
|---|---|---|
| Flash 模式 | 烧录参数为 DIO，运行时实测 QIO | 见 [5.1](#51-flash-模式的两层事实) |
| PSRAM | 8 MB Octal，UXGA 帧缓冲占 384 KB | `fb_count=1`，抓帧期间不做其他大块分配 |
| USB | 原生 USB-Serial-JTAG，无桥片 | 深睡即断串口，调试窗口受限于唤醒会话 |
| SD 卡 | SDMMC 1-bit，无 CS 概念 | 不能用 SPI 模式挂载，BSP 的 `sdspi` 路径不可用 |
| IO 扩展 | CH32V003 经共享 I2C 控制 | PWDN / 功放 / LED 均需先 `bsp_i2c_init()` |
| 摄像头 | 定焦模组，SCCB 走共享 I2C | 无 AF 动作，`af_settle_ms` 默认 0 |
| 按键 | PWR = GPIO15，RTC ext1 低有效 | 可作深睡唤醒源；不可用 GPIO0/BOOT |

## 3. 软件架构

### 3.1 模块划分

| 模块 | 文件 | 职责 |
|---|---|---|
| 主流程 | `main.c` | 会话管理、按键分发、拍照编排、时序打点 |
| 配置 | `app_config.*` | NVS 分组存储、默认值写入、基线版本迁移 |
| 摄像头 | `app_camera.*` | 初始化、抓帧、运行时调参下发、AE 落点回读 |
| 存储 | `app_storage.*` | 挂载重试、`DCIM` 目录、序号对齐、容量检查 |
| 音频 | `app_audio.*` / `app_tones.h` | ES8311 + I2S 播放，7 种提示音 |
| LED | `app_led.*` | EXIO6 状态指示 |
| 电源 | `app_power.*` | 唤醒源判定、长按检测、睡前降流序列 |
| 计时 | `app_session.*` | 统一「保持唤醒」计时，供睡眠与状态查询共用 |
| 命令行 | `app_cmd.*` | 串口 REPL，独立任务 + 阻塞读 |
| 补光 | `app_light.*` | 可选外置灯板，LEDC PWM 控制 |

### 3.2 拍照时序

```
按键事件
   │
   ├─ 容量检查（剩余空间 < 阈值 → 告警，不拍）
   ├─ 挂载 TF 卡（会话内首次需扫卡对齐序号，约 60 ms）
   ├─ 补光点亮（可选）+ 等待 light_lead_ms 让 AE 收敛
   ├─ 快门音（阻塞播放，期间 DMA 持续出流，等效等待 AE 稳定）
   ├─ 抓帧（仅初始化后首张丢一帧）
   ├─ 补光熄灭
   ├─ 写卡（含写后校验）
   ├─ 成功/失败反馈（声音 + LED）
   └─ 重置 hold_awake_s
```

**为什么快门音在抓帧之前**：播放阻塞的 ~200 ms 正好覆盖 AE 重新收敛的时间，省掉一次显式延时。

## 4. 关键设计决策

### 4.1 参数四层结构

```
L1 传感器寄存器默认值   ov5640_settings.h（官方原版，不改）
        ↓
L2 Kconfig 编译期配置   CONFIG_CAMERA_*（官方默认）
        ↓
L3 固件初始化覆盖       app_camera.c 只覆盖 4 项：JPEG、UXGA、quality=12、fb_count=1
        ↓
L4 运行时调参           NVS → app_camera_apply_tuning() → SCCB 写入
```

L4 是本项目的核心设计：**画质参数不写死在代码里**，现场可通过串口调整并持久化。

未启用的调参项：`set_aec2`、`sharpness`（仅寄存器级）、`contrast`、`lenc`、`bpc`、`wpc`。留作后续扩展。

### 4.2 NVS 默认值陷阱与基线迁移

**问题**：`load_*()` 在键不存在时会把编译期默认值**写回 NVS**。这意味着修改代码默认值后，已有设备读到的仍是 NVS 里的旧值——默认值改了个寂寞。

**处置**：引入参数基线版本号。

- 启动时比较 `NVS 中的版本` 与 `编译期版本`
- 落后则**只重置画质类参数**（分辨率、增益上限、降噪、锐度、曝光）
- **不动**现场数据（文件序号、会话时长、音量、补光配置）
- 日志特征：`参数基线版本 0 → 1：自动重置画质类参数为编译期默认值`

**手工兜底**（仅在需要连现场数据一起恢复出厂时）：

```bash
python -m esptool --chip esp32s3 -p <PORT> erase_region 0x9000 0x6000
```

⚠️ 顺序必须是**先烧录 → 后清 NVS → 再复位**。反了的话芯片会用旧固件启动，把旧默认值又写回去。

### 4.3 会话计时与睡眠门控

原设计是「拍完即睡」，但深睡会切断 USB-JTAG，导致串口只有 1~2 秒窗口，无法调试。v1.6 起改为**唤醒会话**模型：

- 上电 / 唤醒 / **每次拍照（成功或失败）** 都重置计时
- 剩余 10 s 播「即将休眠」
- 播完静默入睡
- 会话期间摄像头**常驻**，不逐张 deinit

**取舍**：待机电流略高于「拍完即睡」，但换来 5 分钟的维护窗口。现场使用中这个窗口也便于连续拍摄多张。

### 4.4 按键语义

| 场景 | 行为 | 理由 |
|---|---|---|
| 深睡中首次按下 | 仅唤醒 | 避免取出设备时的误触产生废片 |
| 会话中短按 | 拍照 | 主操作 |
| 长按 > 1.5 s | 立即休眠 | 手动收工，不等超时 |
| 唤醒后立即松开 | 不再触发拍照 | 主循环需先等按键释放（`app_power_wait_button_release`） |

长按阈值经历 2.0 s → 1.5 s 调整：2 s 现场手感偏长，1.5 s 更符合「按住不放」的直觉。

### 4.5 音频反馈设计

7 种提示音，全部内嵌为 PCM 头文件（`app_tones.h`），由 `tools/gen_tones.py` 生成。

| 事件 | 音型 |
|---|---|
| 唤醒 / 上电 | 双音上行 |
| 快门 | 真实单反快门取样（CC0） |
| 拍照成功 | 880 → 1175 Hz 轻柔上行 |
| 拍照失败 | 1046 → 523 Hz 急促下行 |
| TF 卡告警 | 三短音 |
| 低电量 | 500 Hz 持续音 |
| 即将休眠 | 单音提示 |

**硬件限制**：板载喇叭在 ≤ 400 Hz 几乎无输出。早期用 150 Hz / 220 Hz 合成音，实机听不见。改为**持续包络 + ≥ 440 Hz** 后解决。

**不要三连音**：三连音在嘈杂环境易与告警音混淆，成功/失败统一用双音，仅方向不同。

### 4.6 摄像头 EOI 探测窗口补丁

**现象**：全遮光或极暗场景下拍照，JPEG 写卡失败（NO-EOI 超时）。

**根因**：`esp32-camera` v2.1.7 的 `cam_hal.c` 在拼接 JPEG 时，只在**最后一个 DMA 节点**内搜索 EOI 标记。实测 DMA 节点大小仅 1024 B，而暗场短帧的 EOI 可能落在更早的节点里，导致永远找不到。

**补丁**：把探测窗口从「最后一个节点」扩展到「最后 N 个节点」，按帧长动态计算。

- 补丁文件：`tools/patches/cam_hal.c.patched`
- 验证：`grep -c "esp32s3_macro_cam 补丁" managed_components/espressif__esp32-camera/driver/cam_hal.c` ≥ 1
- 为什么不在 git 里直接改托管组件：`managed_components/` 由组件管理器还原，改动会被覆盖，因此以补丁形式随仓库分发

### 4.7 文件序号防覆盖

单靠 NVS 计数器不可靠：清 NVS、换卡、或 NVS 写失败都会导致序号回退，覆盖已有照片。

**方案**：挂卡时扫描卡上 `IMG_*.jpg` 的最大序号，把 NVS 计数器抬到「最大 + 1」。

代价是会话首次挂卡多约 60 ms，但彻底杜绝覆盖。

### 4.8 可选补光模块

外置 LED 灯板，通过空闲 GPIO + LEDC PWM 驱动。

- 默认 `light_en=0`，不点灯
- 支持常亮 / 脉冲两种模式
- 拍照前点亮，抓帧后立即熄灭（写卡不需要光）
- 深睡前把控制脚**固定低电平并 hold**，防止栅极悬空导致微亮漏电

**状态**：实验性模块，默认关闭。灯板选型与光学设计不在本仓库范围内。

## 5. 已知问题与权衡

### 5.1 Flash 模式的两层事实

| 层面 | 实际值 | 说明 |
|---|---|---|
| 烧录参数 / 镜像头 | **DIO** | `build/flash_args` = `--flash_mode dio`，镜像头 byte2 = 0x02 |
| 运行时 | **QIO** | 启动日志 `SPI Mode : QIO` / `flash io: qio` |

`sdkconfig` 里同时存在 `CONFIG_ESPTOOLPY_FLASHMODE_QIO=y` 与字符串 `CONFIG_ESPTOOLPY_FLASHMODE="dio"`，两者状态不一致，属历史配置遗留。

**处置**：**不要手改 sdkconfig 去「修」这个不一致**。现状运行正常，手改只会让 Kconfig 状态更乱。真要改，走 `idf.py menuconfig` 让 Kconfig 重算，然后全量重编。

### 5.2 定焦模组近距失焦（首要画质瓶颈）

出厂对焦点约 1.5 m，而实际工作距离 100 mm。按薄透镜公式估算，弥散圆约 11.5 px，边缘过渡宽度 ≥ 10 px（正常应为 1~2 px）。

这是**光学硬件问题**，软件无法补偿。表现为「雾感」、动态范围收窄（90/255）。评估中的所有参数调优都必须以「先解决失焦」为前提，否则参数对比不可信。

下一步方向：更换 M12 微距镜头模组，或选用带 AF 的模组。

### 5.3 深睡电流未实测

`≤ 20 µA` 是目标值。当前缺测量工具，未取得实测数据，因此续航指标也无法闭环。EXIO3（PWDN）极性同样待深睡电流实测确认。

### 5.4 电量检测未标定

电池分压比与 ADC 量程未标定，`app_power_battery_low()` 当前恒返回 false，低电量告警实际不生效。

### 5.5 TF 卡 0x107 超时

硬复位后偶发 `sdmmc_init_ocr: send_op_cond (1) returned 0x107`，重试 3 次仍失败。只有物理断电（拔插 USB 或重插卡）能恢复。

**预防**：复位前必须先 `app_storage_unmount()` 卸卡；已加 3 次挂载重试。

### 5.6 NVS 键的兼容性

NVS 命名空间沿用历史名称 `crackcam`。**不要修改**——改名会让已部署设备的全部参数失效，且无迁移价值。

## 6. 验证方法

| 项 | 方法 |
|---|---|
| 参数是否真正下发 | `cam show` 回读寄存器值，对比 `cfg list` 的期望值 |
| AE 落点 | `cam show` 显示本帧曝光/增益；注意「当前曝光」原始值**未除以 16** |
| 音效 | `tone <n>` 逐个试听 |
| 按键语义 | `btn 10` 监听电平，配合串口日志确认长按/短按判定 |
| 深睡 | 静置至超时，观察串口消失；按 PWR 恢复 |
| 序号防覆盖 | 拍若干张 → 清 NVS → 再拍，确认序号从卡上最大值继续 |
| 补丁有效性 | 全遮光环境下拍照，确认能正常落卡 |
